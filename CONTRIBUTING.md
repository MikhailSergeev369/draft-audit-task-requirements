# Contributing

This repository develops an individual Internet-Draft. Comments, issues,
pull requests, and manuscript changes intended for that work are contributions
to the IETF process. Please read the [IETF Note Well](https://www.ietf.org/about/note-well/),
[BCP 78](https://www.rfc-editor.org/info/bcp78),
[BCP 79](https://www.rfc-editor.org/info/bcp79), and the
[IETF Trust Legal Provisions](https://trustee.ietf.org/license-info).
Contribute only material you are entitled to provide under the applicable terms.
See [LICENSE.md](LICENSE.md) for the separate tooling license.

## A useful contribution

Identify the section or stable XML anchor, the ambiguity or claim at issue,
and a concrete example or proposed wording. Link public sources when relevant.
An issue or an email is enough to start; a pull request is not required.

Edit only `draft-sergeev-audit-task-requirements.xml` for manuscript changes.
Run `make review`, `make check`, `make test`, and, when the formatter is
installed, `make build`. Include the regenerated reading copy in the PR.
Do not hand-edit TXT, HTML, or `review/editor-copy.md`. Do not change the
published -00 snapshot to make a comparison pass.

Keep substantive changes separate from broad formatting changes where possible.
The editor reviews scope and CI results, records the reason for a disposition,
and retains material disagreement. A merge is not an IETF consensus decision.
Substantive points relevant to AUDIT can also be discussed on
[audit@ietf.org](mailto:audit@ietf.org); contributions by mail are welcome.

## Attribution, authorship, and privacy

Preserve attribution for substantive contributions and update acknowledgments
when appropriate. Acknowledgment does not imply endorsement. Review, commit
counts, and repository access do not automatically confer authorship; any
change to I-D authorship is discussed explicitly with the people concerned.

Do not post private correspondence, unpublished partner drafts, credentials,
personal data, or operational evidence without permission. Use public links
for public mailing-list contributions. Treat others respectfully, in line
with the IETF participation guidelines linked from the Note Well.

There is no separate CLA, signed editor-decision form, or automatic publication
approval in this repository. Ordinary IETF contributor obligations remain.

## External reports and dispositions

See [ISSUE-PROCESS.md](ISSUE-PROCESS.md) for response targets, review,
public dispositions, closure, and the distinction between working changes
and a posted I-D. Questions by issue or email are welcome without a patch.
